# Backlog priorisé — écarts vs cahier des charges

Comparatif entre le cahier des charges et l'état actuel de "Missions d'Ambre" (PWA React/Vite + Firebase). Priorités : **P0** (cœur de l'expérience, impact direct enfant/parent), **P1** (gamification/engagement importants), **P2** (confort, secondaire).

**Statut au 11/08 : les 30 tâches du backlog sont toutes ✅ terminées**, tests + build vérifiés après chaque lot (338/338 tests, build OK). La divergence de stack technique a aussi été tranchée avec l'utilisateur (voir en fin de document) : on reste sur la PWA Vite + Firebase actuelle, pas de migration native prévue.

Ce choix est assumé, pas un oubli : pas de dépendance réseau ni de coût d'API pour générer une mission, fonctionnement garanti hors-ligne (PWA), latence nulle, et pas de risque qu'une IA génère un énoncé mathématiquement incorrect pour un enfant de CE2. La notion de "repli en cas d'échec de l'IA" ne s'applique donc pas : il n'y a rien à répliquer, la génération ne peut pas échouer.

## Divergence de stack — tranchée avec l'utilisateur le 11/08

- **Décision : on reste sur la stack actuelle (Vite PWA + Firebase)**, pas de migration vers React Native/Expo + FastAPI + MongoDB + LLM. Raison : usage familial uniquement (tablettes à la maison), pas de diffusion App Store / Play Store prévue, et les fonctionnalités natives (notifications push, vibrations riches, icône d'accueil sans étape navigateur) ne sont pas jugées essentielles — la PWA actuelle couvre déjà l'installation sur écran d'accueil, le fonctionnement hors-ligne et la vibration basique (`navigator.vibrate`). Cette décision peut être révisée plus tard si l'objectif change (ex. diffusion publique).
